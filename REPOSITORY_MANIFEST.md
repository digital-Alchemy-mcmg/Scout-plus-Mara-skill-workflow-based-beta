# MARA/SCOUT Repository Manifest

## 1. System Overview
**System Name:** MARA + SCOUT Query-Resolved Candidate Projection Pipeline  
**Architecture Type:** Three-Machine Governed Translation Pipeline  
**Primary Logic:** Read First → Represent Second → Bind Third → Project Fourth

## 2. Machine Definitions
The repository is organized around three distinct architectural machines:
- **SCOUT (Target Compiler):** decomposes source job postings into demand primitives.
- **MARA (Evidence / Binding Engine):** constructs and freezes Spatial Candidate DNA, governs evidence/provenance, traverses demand against the frozen candidate, and may halt at mandatory artifact requirements that cannot be legally resolved.
- **ARTIFACT MODEL (Projection Renderer):** consumes governed MARA exhaust / logical artifact payload, selects a valid retained surface, and renders without changing candidate truth.

## 5. Current Governing Additions — 2026-08-18

The 2026-08-18 synchronization explicitly admits:

1. **Six-year candidate chronology accountability before freeze** — accountability may come from employment, education, projects, entrepreneurial activity, professional development, or declared gaps. Temporal spans may not exceed evidence.
2. **`USER_OVERRIDE`** — operational, not evidentiary authority for a mandatory artifact requirement MARA cannot legally resolve. Literal user input and override propagation are measured separately on the canonical pre-render artifact representation.
3. **Deterministic résumé surface registry** — fixed logical payload first, geometry second. Candidate truth may never be rewritten to rescue a surface.
4. **Behavioral receipt retention** — UO-001 validated the chronology halt/override/refreeze path and produced a corrected 41-line logical résumé payload ready for surface reconciliation.

## 6. Maintenance Rules

- **Canonical Terminology:** Candidate Core is not an evidence domain; the evidence registry contains five candidate evidence domains.
- **Traceability:** every schema, override event, rendered assertion, or logic gate must be traceable to its governing authority.
- **Dependency Order:** architecture → schemas/contracts → workflows/logic → rendering.
- **No Silent Expansion:** architecture exposed during implementation must be surfaced for explicit synchronization rather than silently added.
- **Provenance Invariance:** surface geometry, responsive wrapping, typography, or pagination cannot alter candidate truth or User Override attribution.
- **Surface Discipline:** fix the logical payload first; select geometry second; never rewrite candidate truth to rescue a surface.
